# Google の OAuth クライアントを用意する

`login` を使う前に、1回だけ行う。シークレットが漏れたときは「4. OAuth クライアントを作る」からやり直す。

## 1. プロジェクトを作る

- 個人用の Google アカウントで [Google Cloud コンソール](https://console.cloud.google.com/) を開く
  - 仕事用の Workspace で作ると「内部」にでき警告画面も出ないが、個人用アカウントでログインできなくなる
- プロジェクトを新しく作る。名前は `multi-account-mcp`
  - プロジェクト ID は自動で入る。ほかの人が使っていれば数字が付くが、そのままでよい

## 2. API を有効にする

「API とサービス」→「ライブラリ」で、次の2つを有効にする。

- Google Drive API
- Google Sheets API

## 3. 同意画面を作り、本番にする

「Google Auth Platform」で行う。

| 画面 | 設定 |
|---|---|
| ブランディング | アプリ名は `Multi-Account MCP`。ユーザーサポートメールとデベロッパーの連絡先は個人用のアドレス。ホームページは `https://github.com/Alfr0475/multi-account-mcp`、プライバシー ポリシーは `https://github.com/Alfr0475/multi-account-mcp/blob/main/PRIVACY.md`、承認済みドメインは `github.com`。ロゴは入れない（入れると公開のときに確認を求められる） |
| 対象 | ユーザーの種類は「外部」。作ったあと「アプリを公開」を押して、公開ステータスを「本番環境」にする |
| データアクセス | スコープは登録しない（下の注を参照） |

- 「テスト中」のままだと、リフレッシュトークンが7日で切れる（`docs/decisions.md` の 18）
- スコープを登録しないのは、`drive` が「制限付き」のスコープで、登録すると公開のときに審査を求められるため。審査を受けない場合でも、ログインのときにスコープを求めれば使える（2026-11-02 に個人用・仕事用の両方で確認）
  - 個人用アカウントでは、ログインのとき「このアプリは Google で確認されていません」と出る。「詳細」→「Multi-Account MCP（安全ではないページ）に移動」で進む
  - 仕事用アカウントでは、5. でこのアプリを信頼済みにしていれば出ない

## 4. OAuth クライアントを作る

「Google Auth Platform」→「クライアント」→「クライアントを作成」。

- アプリケーションの種類は「デスクトップ アプリ」。名前は `multi-account-mcp`
  - デスクトップ アプリなら、`login` がブラウザから受け取るリダイレクト先（`http://127.0.0.1:<空いているポート>`）を登録しなくてよい
- 作成直後の画面に出るクライアント ID とクライアント シークレットを、すぐ 1Password に入れる
  - **シークレットは作成直後にしか表示されない。** JSON のダウンロードもこの画面でしかできない。JSON はディスクに残さない
  - 入れ先は保管庫「Multi-Account MCP」の項目 `google-oauth-client`。フィールド `client_id` と `client_secret` に入れる

## 5. 仕事用の Workspace で、このアプリを信頼済みにする

仕事用の管理者アカウントで [管理コンソール](https://admin.google.com/) を開く。

- 「セキュリティ」→「アクセスとデータ管理」→「API の制御」→「サードパーティ製アプリのアクセスを管理」
- 「新しいアプリを設定」で、4. のクライアント ID を検索して選ぶ
- 対象は自分が入っている組織部門（迷ったら全体）。アクセス権は「信頼できる」

## 6. 確かめる

- Google Cloud の「対象」で、公開ステータスが「本番環境」になっている
- 1Password の `google-oauth-client` に、`client_id` と `client_secret` の両方が入っている
- 管理コンソールで、`Multi-Account MCP` が「信頼できる」になっている
