# 決定記録

設計段階（ideas-vault）で決めたこと。ここで退けた案は、ユーザーの確認なしに出し直さない。

## 1. 対象は Google から始める

- **決めたこと**: 最初に対応するサービスは Google。他のサービスは後から足せる作りにする
- **理由**: 記録なし
- **退けた案**: 記録なし

## 2. ローカル MCP（stdio）にする

- **決めたこと**: 手元で動かすローカル MCP にし、通信は stdio
- **理由**: スマホでは使わず、普段使うのは Claude Code と Claude Desktop のため
- **退けた案**: リモート MCP（Streamable HTTP、claude.ai のカスタムコネクタ）。上の理由で必要がない。ブラウザの claude.ai から使えないことは承知のうえ。リモート化が必要になったら通信の層だけ差し替える

## 3. 最初の範囲は個人用と仕事用の Google アカウント、Drive と Sheets

- **決めたこと**: 最初の組み合わせは個人用と仕事用の Google アカウント。対象は Drive と Sheets
- **理由**: 困っているのが個人用と仕事用の組み合わせのため。きっかけは、仕事用の作業報告書のスプシを、個人用に繋いだコネクタで直そうとして「アクセス権が無い」と言われたこと
- **退けた案**: 記録なし

## 4. アカウントは自動で解決する

- **決めたこと**: ユーザーにも Claude にも、普段はアカウントを選ばせない
  - ファイル ID・URL での操作: アクセスできるアカウントを順に試し、どのファイルがどのアカウントかを覚えておく
  - 検索: 全アカウントを横断し、結果にアカウント名を付けて返す
  - `account` 引数は、明示したいときだけ使う任意の引数にする
- **理由**: 作業中にコネクタを繋ぎ直すのが面倒で、どのアカウントのファイルかを意識したくない（コア体験）
- **退けた案**: 呼び出しのたびにアカウントを明示して指定する方式（既存の OSS はどれもこの方式）。コア体験に合わない

## 5. アカウントをまたぐ操作は想定しない

- **決めたこと**: 1つのタスクでアカウントをまたぐ操作（例: 個人用から仕事用へのファイル移動）は、今は想定しない
- **理由**: 横断するタスクは少ないため
- **退けた案**: 記録なし

## 6. 新しいファイルを作るときのアカウントの決め方

- **決めたこと**: 次の順で決める。既定のアカウントは置かない
  1. 作る先のフォルダが指定されている → そのフォルダがあるアカウント
  2. 既存のファイルを元にしている（コピー・「同じ場所に」など）→ 元のファイルのアカウント
  3. どちらでもない → ツールがエラーを返し、Claude にユーザーへ聞かせる
- **理由**: 作り先を間違えたときの被害が大きいため
- **退けた案**: 既定のアカウントを置く（迷ったら必ず個人用、など）。間違えると気づかないまま残る

## 7. 自作する

- **決めたこと**: 既存の OSS は使わず、自作する
- **理由**: OSS は中身の実装が見えにくく、Google の2アカウント分の権限を預けるにはセキュリティ面で信用しきれない。自作ならすべてを自分で管理できる
- **退けた案**: 既存の OSS（`bakissation/mcp-google-multi`、`aaronsb/google-workspace-mcp`、`@mindstone/mcp-server-google-workspace`、`taylorwilsdon/google_workspace_mcp`）。上の理由と、どれもアカウントを明示する方式でコア体験に合わないため。詳細は `docs/design.md` の「競合・代替手段」

## 8. 実装言語は TypeScript

- **決めたこと**: TypeScript で書く。ランタイム（Node）は mise で入れる
- **理由**: 公式 MCP SDK が一番成熟しているため（どの言語にも特に慣れていないので、SDK の成熟度で選んだ）
- **退けた案**: 記録なし

## 9. Google API は必要な API の個別パッケージだけを使う

- **決めたこと**: `@googleapis/drive` と `@googleapis/sheets` を使う
- **理由**: 必要な API だけに絞り、依存を小さくするため
- **退けた案**: 巨大な `googleapis` パッケージ

## 10. 権限は `drive` ＋ `spreadsheets`。強い権限の分、ツールの側で絞る

- **決めたこと**: スコープは `drive`（フルアクセス）と `spreadsheets`。代わりに次の3点で絞る
  - 削除はゴミ箱への移動だけ（30日以内なら戻せる）。完全削除のツールは作らない
  - 共有設定を変えるツールは作らない（外部への漏えいを防ぐ）
  - ツールを危険度ごとに分ける（読む／書く・作る／削除）。Claude Code の permissions で、読むツールは自動許可、削除は毎回確認、のように設定できるようにする。削除などのツールには MCP の `destructiveHint` を付ける
- **理由**: ファイルの作成・削除も Claude にさせるため
- **退けた案**: 記録なし

## 11. 最初のバージョンのツールは10個

- **決めたこと**: `list_accounts`、`drive_search`、`drive_read`、`sheets_read`、`sheets_write`、`sheets_append`、`drive_create`、`drive_copy`、`drive_rename`、`drive_trash`。足りないものは使いながら足す
- **理由**: 記録なし
- **退けた案**: 次は後回し
  - `drive_move`（フォルダの移動）
  - Google ドキュメントへの書き込み（Docs API と追加の権限が要るため）

## 12. トークンは 1Password に置き、設定ファイルには秘密情報を書かない

- **決めたこと**: リフレッシュトークンと OAuth クライアントのシークレットを、1Password の専用の保管庫に置く（`op` CLI で読み書き）。設定ファイル `~/.config/multi-account-mcp/` には、アカウント一覧と「ファイル→アカウント」の記録だけを置く。保管場所は差し替えられる作りにする
- **理由**: パスワード類は 1Password に集約する方針に合わせるため
- **退けた案**: macOS キーチェーン（キーチェーンは使わない方針のため）

## 13. `op` からは最初に1回だけ読み、あとはメモリに持つ

- **決めたこと**: 最初にツールが使われたときに1回だけ 1Password から読む。アクセストークン（1時間で切れる）はメモリの中だけで更新し、1Password には書き戻さない。1Password に書くのは `login` のときだけ
- **理由**: `op` は承認が10分で切れ、呼ぶたびに Touch ID を求めるため。セッションで最初に Drive を触ったときに Touch ID を1回求められる形になり、勝手に使われないための関所にもなる
- **退けた案**: 記録なし

## 14. アカウントの追加・削除は CLI で行う

- **決めたこと**: `login`（ブラウザで Google のログイン画面を開き、トークンを 1Password に保存）と `logout`（トークンを Google 側で取り消してから 1Password から消す）を用意する。MCP サーバー本体はログインの画面を持たず、保存済みのトークンを読むだけ
- **理由**: 記録なし（`logout` については、Mac を手放す前に古いトークンを取り消せるようにするため）
- **退けた案**: 記録なし

## 15. インストールは ghq で clone してビルドし、`register` で登録する

- **決めたこと**: リポジトリを ghq で clone してビルドする。npm には公開しない。`register` コマンドで、mise で入れた Node の絶対パスを調べて、Claude Code（ユーザースコープ）と Claude Desktop の設定にサーバーを登録する。Node の更新や Mac の買い替えのときは `register` を打ち直す
- **理由**: Claude Desktop はシェルの設定を読まずにサーバーを起動するので、Node を絶対パスで登録する必要があるため。npm に公開しないのは、自分専用で公開しないため
- **退けた案**: 記録なし

## 16. 操作ログは1ファイルに残す

- **決めたこと**: 書く・作る・削除のツールが呼ばれるたびに、日時・ツール名・アカウント・ファイル ID とファイル名・成否を `~/Library/Logs/multi-account-mcp.log` に1行で書く。トークン、ファイルの中身、セルの値は書かない。デバッグ用の出力は標準エラー出力へ（標準出力は MCP の通信に使う）
- **理由**: 誤操作をしたときに、何をどこにしたかを追えるようにするため。秘密情報を書かないのは、ログが漏れても被害が出ないようにするため
- **退けた案**: ログのローテーション。1日200回操作しても1年で15MB程度のため不要。大きくなりすぎたら見直す

## 17. 中身を3層に分ける

- **決めたこと**: 通信の層（stdio／将来 Streamable HTTP）、共通の層（アカウント台帳・トークン保管・ツールの登録）、サービス層（`google/` など）に分ける
- **理由**: サービスの追加とリモート化のどちらにも対応できるようにするため
- **退けた案**: 記録なし

## 18. トークンの7日失効は、OAuth アプリの本番化で対処する

- **決めたこと**: OAuth アプリを「外部」かつ「本番」にする（審査は受けない）。仕事用の Workspace 側では、管理コンソールでこのアプリを「信頼済み」にする。本番化してからログインし直す
- **理由**: 「テスト中」のままだとリフレッシュトークンが7日で失効するため。未審査アプリの警告画面は出るが、100 ユーザーまでなら使える。仕事用の Workspace は管理者が自分で、外部アプリのルールもない
- **退けた案**: 「テスト中」のまま使う（7日ごとにログインし直すことになる）

## 19. 名前と表記

- **決めたこと**: 名前は `multi-account-mcp`。表示名は Multi-Account MCP とし、場所によって表記を分ける（使い分けは `docs/design.md` の「名前の表記」）
- **理由**: 説明的で迷わないため
- **退けた案**: 記録なし

## 20. 開発環境は Dev Container の例外にし、Mac の上で直接開発する

- **決めたこと**: Dev Container は使わず、Mac の上で開発・実行する。代わりに、Mac の環境を汚さないよう次を守る
  - Node はリポジトリ直下の `mise.toml` でパッチまで固定する（グローバルには入れない）。`register` が Node の絶対パスを登録するので、更新したら `register` を打ち直す
  - npm パッケージはリポジトリの `node_modules` だけに入れる。`npm -g` は使わず、ツールは devDependencies に入れて `npm run` / `npx` で呼ぶ
  - `.npmrc` に `ignore-scripts=true` を書き、依存の install スクリプトをホスト上で動かさない。依存は最小限にし、lockfile をコミットして `npm ci` で入れる
  - 設定フォルダとログの場所は環境変数で差し替えられるようにし、テストや開発中は一時ディレクトリを使う
  - `register` と対になる `unregister` を用意する。`logout` → `unregister` → リポジトリ削除 → `mise uninstall node@<ver>` で元に戻せるようにする
- **理由**: このサーバーは Claude Code・Claude Desktop が Mac の上で直接起動し、1Password の Touch ID も `~/Library/Logs` も Mac の上でしか使えないため。Dev Container を選んでいたのは Mac の環境を汚さないためで、DB などのミドルウェアを使わないこのプロジェクトでは、上の対策で同じ目的を果たせる
- **退けた案**: 開発とテストは Dev Container の中で行い、Claude に登録して動かすときだけ Mac の上で動かす。環境が2つに分かれ、`op` と Touch ID、ログの周りがコンテナの中では試せないため
